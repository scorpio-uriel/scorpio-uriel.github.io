Projet phare

Un assistant qui répond à partir des documents de l'entreprise, et qui cite ses sources

Open source · MIT

Enterprise RAG Assistant

Posez vos questions à la documentation interne et obtenez une réponse sourcée, en streaming, 100 % en local.

Les administrateurs importent les documents (politiques RH, procédures, guides IT), les employés posent leurs questions en langage naturel. Chaque réponse s'appuie uniquement sur ces documents. Quand l'information n'y figure pas, l'assistant le dit au lieu d'inventer. Le LLM et les embeddings tournent avec Ollama : aucune donnée ne quitte l'infrastructure.

Quel est le menu de la cantine demain ?
Je ne trouve pas cette information dans les documents disponibles.

Sous le seuil de similarité, la réponse de refus est renvoyée sans appeler le LLM.

Chat en streaming

La réponse arrive token par token via SSE, puis la liste des sources.

Citations vérifiables

Document, page, extrait et score de similarité pour chaque réponse.

Refus hors corpus

Sous un seuil de similarité, refus immédiat sans appel au LLM pour limiter les hallucinations.

Ingestion asynchrone

PDF, DOCX, Markdown, TXT. Contrôle du type MIME réel, doublons détectés par SHA-256, statut suivi.

Mémoire de conversation

Les questions de suivi tiennent compte des échanges précédents, historique persisté par utilisateur.

Sécurité par rôles

JWT, mots de passe BCrypt, rôles ADMIN et USER, conversations isolées entre utilisateurs.

Le pipeline RAG

Deux flux autour d'une même base. L'ingestion remplit pgvector en arrière-plan ; chaque question y cherche les passages les plus proches avant de décider s'il y a de quoi répondre.

Stack et choix techniques

CoucheChoix
BackendJava 21, Spring Boot 4.1. Monolithe modulaire par fonctionnalité (auth, document, chat), couches controller → service → repository.
IASpring AI 2.0. ChatClient, EmbeddingModel et VectorStore : on change de fournisseur sans réécrire la logique.
ModèlesOllama (llama3.2, nomic-embed-text), gratuit et local.
DonnéesPostgreSQL + pgvector, une seule base pour le métier et les vecteurs. Schéma versionné par Flyway.
SécuritéSpring Security, resource server JWT, API stateless.
FrontendReact 19, TypeScript, Vite, TanStack Query, Tailwind.
ExécutionDocker Compose, images multi-stage, nginx avec streaming préservé.

Qualité et tests

  • Tests d'intégration sur un vrai PostgreSQL + pgvector avec Testcontainers.
  • RAG testé sans LLM : modèle d'embedding déterministe et ChatModel mocké, en quelques millisecondes.
  • Front testé avec Vitest, Testing Library et MSW, flux SSE compris.
  • CI GitHub Actions : formatage Spotless et tests côté Java ; lint, typecheck, tests et build côté React.

Lancer la démo

$ git clone https://github.com/scorpio-uriel/enterprise-rag-assistant.git
$ cd enterprise-rag-assistant
$ cp .env.example .env
$ docker compose up --build

Puis http://localhost:8080. Environ 8 Go de RAM ; les modèles sont téléchargés au premier lancement.

Pistes d'évolution identifiées : recherche hybride BM25 + vecteurs et re-ranking, OCR pour les PDF scannés, JWT en cookie HttpOnly, SSO/OIDC.
